# 传奇一瞬

这是我发布的 Android 照片处理应用，主要做调色、景深虚化和智能构图，也可以手动选择需要保持清晰的主体。照片处理在手机上离线完成。

我以个人非商业使用许可公开 2.8.3（versionCode 81）版本的源码，供个人学习、修改和使用。作为本项目的发布者，我提供应用源码和两份自有调色模型；第三方代码和模型的权利仍归各自权利人所有。

源码中不包含安装包、我的签名密钥、照片样例或训练数据。第三方模型不附带权重，来源和准备方法见模型说明。

功能

调色：徕卡冷调 / 徕卡暖调两种独立模型，输出低频色彩后与原图细节融合。包含调色的流程显示二选一按钮，记住上次选择；首次默认冷调。切换后点击显影才应用，不自动处理或保存，旧成片保留并标注其实际风格。

景深：手动选焦点、调整光圈；相对深度配合神经虚化和高光散射生成景深效果。

主体保护：可选功能，默认关闭。支持多个保护点，逐点完成并持久保存蒙版，退出或恢复后只计算缺失项，接触主体合并后再参与渲染。2.5.2 针对“算完仍显示未完成”修正选择身份、完成标记与异步刷新；页面返回和 App 恢复仍需真机确认，不把界面快照当作模型已完成。

构图：用 GAIC 给候选裁框评分。选方案、应用裁框和保存是分开的操作；应用已有成片的裁框不会重新调色或虚化。

导出：只有选择虚化时显示原图像素、长边 2048 和 1024 三档。不选虚化时自动保留可用原像素，最高 5000 万像素；超过上限才等比缩小，小图和裁框内像素不足时不放大。SDR 成片可选 PNG、JPEG Q95、WebP Q90/Q95 或受系统支持的无损 WebP；格式选择不重新运行模型，体积提示只是估计。Android 14 及以上增加 SDR 基底 Ultra HDR JPEG 的识别、配对处理和导出；实际目标具有 HDR 成片时，导出菜单显示 Ultra HDR JPG。不是对任意 HEIF、PQ、HLG、高位深或广色域原编码的无损保留。

HDR 显示与显影：Android 14+ 的受支持 Ultra HDR JPEG 使用真实增益图预览。HDR 输入的底部操作为「导入｜HDR显影｜SDR显影｜导出」，权重 `.5:1:1:.5`（不含间距）；SDR 输入和仅构图流程保留原布局。显式选择进入独立缓存和恢复状态；HDR 显影或导出失败直接报错，不自动降 SDR，SDR 显影不复用 HDR 成片。不支持 HDR 的屏幕明确提示按 SDR 显示，不把标识或窗口请求当成真实 HDR 亮度验收。

参数：成片成功生成并呈现后自动收起，失败或取消不触发。需要接着构图时仍显示方案，应用后再收起；可手动通过“参数”重新展开，换图重新展开。

空间预览：深度网格支持旋转、平移、缩放和全屏；全屏陀螺仪视差默认关闭，可校准。它是单张照片的深度展示，不是三维重建。

会话恢复：在本机私有目录保留最近一张照片的检查点，不积累历史。先完成不可变像素文件，再原子提交清单；损坏记录显式报错并保留证据。它不是加密备份，也不保证来源访问权限被撤销后仍能继续处理。主体分析可选长边 2048、1220 或 720，默认 2048；改变分析档位需重新计算相应缓存。

本次改动和验证边界见 [版本记录](docs/CHANGELOG.md)。

2.6.0 新增外接模式：用户选择相机目录并启动后，先跳过全部现有照片，只处理监听就绪后新增且稳定的照片；停止/重启不补跑历史。默认保留原片，可单独危险确认成功保存后处置；保存发布失败、原片身份变化或成片指纹核验失败不删原片。2.8 开启删除前会重新说明风险：明确同意后，即使动态视频、源 HDR、人像编辑数据或部分拍摄信息未全部转存，也可尝试删除；删除可能不可恢复。旧版删除选择升级后须重新确认，不补删旧照片。支持 SDR 或能力允许时优先 HDR、可选悬浮进度与运行参数通知。编辑导出新增默认关闭的“徕卡一瞬相册标识”，开启仅 JPEG（含真实 Ultra HDR），只写候选元数据、不加画面水印；厂商协议及实际相册显示未确认。编辑参数布局、展开收起与最终裁剪帧交接、监测卡片和详情同步完善。详见 [外接与编辑使用说明](docs/EXTERNAL-MODE.md)。

2.5.2 同步了非虚化 HDR 的无损 Float32 文件与有界行交接、按行增益图编码，以及近原尺寸源 HDR 行复用、插值轴预计算和精确线性值复用；同时同步调色融合与光学辅助的等价内存/计算优化。保持既有尺寸、采样/累加顺序、HDR 元数据与 JPEG 质量策略，不通过缩图、降低精度或 OOM 转 SDR 掩盖失败。文件交接增加磁盘空间和读写，完整 HDR 虚化仍有整幅分配；本次没有公开树的完整真机性能或内存结论。

2.5.1 同步了 RAW/DNG 原像素尺寸核验、导入失败保留上一张照片、无区域解码器时的全像素读取，以及通用 PureLut 三线性查表代码和合成测试。它不是新的 RAW 解码引擎，真实相机 DNG 仍待设备验收。公开版仍只提供上述冷暖两种风格；私有成品风格的 LUT 节点、接线和保护实现不随本仓库发布，通用查表代码不会改变现有冷暖模型输出。

App 没有联网权限。照片在设备上处理；构建时下载依赖、开发者自行准备模型，与 App 运行时联网是两回事。

开始使用

需要 JDK 17、Android SDK 35 和支持 AGP 8.7 的 Android Studio；最低运行版本是 Android 8.0（API 26）。Gradle Wrapper 已包含。

```bash
# macOS / Linux 首次使用时
chmod +x gradlew
./gradlew :app:assembleDebug
```

Windows 使用：

```powershell
.\gradlew.bat :app:assembleDebug
```

第一次构建会下载依赖。SDK 路径由 Android Studio 写入本地 local.properties，不要提交这个文件。

缺少第三方模型时仍可编译，但这不代表对应功能能运行。只使用调色时可用已包含的模型；景深、智能构图、主体保护分别需要额外资产。先看模型说明（docs/MODELS.md），准备后用 python tools/check_models.py 检查。

详细步骤见构建说明（docs/BUILDING.md）。代码入口和处理尺寸见实现说明（docs/ARCHITECTURE.md）。


## 2.8.1 手动编辑保存修复

手动编辑保存时，越界或截断的 Interop 目录不再阻断保存：保留边界检查，只跳过该目录的成片链接并提示用户。原图不改不删，原始元数据字节仍保存在经过回读核验的归档中；归档不保证其他相册可读取。其他目录、冲突、未知类型和真实 I/O、权限、取消仍严格处理。外接和删除策略不变，不改照片像素、调色、虚化、尺寸、精度或 HDR。

## 2.8.3 监听置顶与HDR提亮

外接模式“开始监听”“停止监听”移到标题下、说明与权限之前，仅移动原有控件；启停回调、就绪和权限检查、按钮可用状态、扫描/队列/原片处置不变。同步2.8.2的新HDR成片1.25倍线性RGB增益（约+0.32EV）：SDR底图、调色/虚化、尺寸、精度和质量不变；原始检查点不曝光，最终交接仅应用一次，裁剪/缩放/恢复/重复保存不叠加。须重新HDR显影，旧成片和仅构图不额外提亮；越界/取消/I/O仍失败，不截断或因提亮溢出转SDR。实际屏幕亮度不保证增加25%，本次不是恢复2.6.0的整套虚化观感，也不是对“第二次导出缺元数据”问题的修复。

布局静态回归：`python tools/check_external_controls.py`。
